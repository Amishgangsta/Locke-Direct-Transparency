# Limitations and Boundaries

**Product:** Locke Direct
**Repository type:** Public technical reference
**Source code:** Not included
**Operator:** Locke Development
**Official site:** <https://www.lockedirect.com>
**Last verified:** 2026-08-20

- Locke Direct is not a law firm, does not represent the user, and does not provide legal advice or legal services.
- A document system cannot determine every fact-specific legal consequence. Customers remain responsible for reviewing the output and deciding whether it fits their situation.
- Laws and execution requirements differ by jurisdiction and change over time. Jurisdiction-specific content requires ongoing maintenance.
- Ask Locke has probabilistic behavior and can be unavailable or misunderstand a request. It is an assistance feature, not the authoritative legal-document generator.
- First-party electronic signing and integrity records are implemented, but the current product should not be represented as an independently authenticated multi-party e-signature platform. Signers are not presented here as independently authenticated participants merely because a record can contain multiple signer entries.
- Automated tests and security controls can contain defects despite passing results. No absolute security claim is made.
- Production configuration and external-provider operations require owner verification beyond source tests. The latest release record did not include a controlled real-money Stripe transaction.
- Retention cleanup has bounded batch logic and a best-effort request/process scheduler; durable scheduled-job verification remains operational work.
- Public technical documentation can lag a production release briefly. Every current record carries a verification date and revision where available.
